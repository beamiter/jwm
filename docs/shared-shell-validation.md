## Acceptance gates

The generic fixture starts a private Xvfb and D-Bus session, verifies the selected top surface paints above the wallpaper, verifies three registered shared panels, checks pinned reservations, clicks a workspace in the shared left panel and rejects an old-session action.

The sparse fixture uses real clients on original tags **1, 3 and 8**, plus empty active tag **5**. It verifies all four displayed pills, retains and highlights the empty active tag, checks secondary-button multi-selection, maps the second displayed pill to original tag 3, cycles the wheel through eligible original tags, and confirms the clients—including the minimized tag-3 client—survive the interactions. Both WM backends pass for every frontend.

The 1280×800 light-theme captures are checked at nine fixed points. Three material points are compared with the actual TaoGlow reference (maximum per-channel difference 8); three outer-boundary points use a limit of 4; three corner points must match the same-run wallpaper within 4. [The reference manifest](../artifacts/header-alignment/header-material-reference.json) records coordinates, colors and the reference screenshot hash. [Positive and negative controls](../artifacts/header-alignment/material-acceptance-controls/summary.json) accept two corrected renderings and reject the old raw-X11 frame, Xilem white fill and opaque Tauri fill.

All result JSON and PNG files are read and validated before a bounded eight-worker file-fsync batch; containing directories are then fsynced before the final inventory is atomically replaced. Earlier passes cannot override a changed binary hash or a failed material gate.

## Build and rendering environment

The matrix uses private X11 sessions with explicit Mesa software rendering: `WGPU_BACKEND=gl`, an invalid Vulkan ICD path, `LIBGL_ALWAYS_SOFTWARE=1`, Mesa GLX and Mesa EGL vendor manifests. Per-case environments are retained in the inventory. Later runs and the CI job also limit llvmpipe to two threads. These settings isolate test graphics and do not select a production GPU backend.

The Ubuntu GTK3/WebKitGTK toolchain is recorded in the inventory. GTK4 and Relm use the pinned Nix GTK 4.22.4/libadwaita 1.9.2 environment and run outside `nix develop` with the same binaries and retained Nix RUNPATHs; this does not establish compatibility with Ubuntu's older system GTK4.

The raw X11rb/XCB frontends and Iced publish the configured bar identity before mapping, so JWM's compositor uses the same header treatment as TaoGlow. Egui, GPUI, Iced and Xilem require native ARGB evidence for the GLES alpha exception and retain opaque fallback without a compositor. The native-renderer reports include real no-compositor checks. The narrow Masonry patch premultiplies verified X11 ARGB GLES output while preserving the advertised WSI alpha mode.

Tauri clears native WebKit backing and uses the shared palette; it preserves an explicit user request for legacy Cairo compositing. Dioxus retains its hidden-create/first-effect-show ordering so its first sparse frame paints without a test remap. Native wheel handling remains connected to the original GDK wheel event. Browser assets and their hashes are recorded per host; production Leptos keeps optional Binaryen postprocessing disabled.

[Dependency-pin evidence](../artifacts/header-alignment/dependency-pins/summary.json) verifies that both Pixels frontends select exactly `pixels = "=0.17.2"`, with unchanged binaries and lockfiles. Xilem and its vendored Masonry companion select commit `78d4f4b6878a1c2e2884edd72d7ecd83f1f6f704`; the offline refresh changes no package version. Its final rebuilt and retested binary is `f8b2d79e2f7dca60bf81771c3e4145d571fec1e9b741311b3eeae8c633e2a5d8`.
